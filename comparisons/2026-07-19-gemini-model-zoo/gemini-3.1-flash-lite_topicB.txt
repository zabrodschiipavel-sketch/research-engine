## Отчёт: Графовый поиск и GraphRAG для научных обзоров

Для создания качественного исследовательского инструмента недостаточно полагаться только на векторный поиск (семантическое сходство). Текстовые модели часто упускают контекстуальные связи, которые в науке эксплицитно заданы структурой цитирований.

## 1. Retrieval через граф цитирований
Поиск по графу (Graph Expansion) превращает поиск статьи из «точечного удара» в «исследование окрестностей». 

Основные методы:
*   **Forward/Backward Snowballing:** Традиционный подход. Взяв «сид-статью», мы получаем доступ ко всем работам, на которые она ссылается (истоки), и ко всем, кто процитировал её (развитие). Это позволяет отследить эволюцию научной идеи.
*   **Ко-цитирование и библиографическое сочетание:** Две статьи считаются связанными, если они часто цитируются вместе или ссылаются на одни и те же источники. Это позволяет находить «неявные» связи — статьи из одной области, даже если авторы не ссылаются напрямую друг на друга.

Преимущество перед чистым текстом в том, что граф отражает **социально-научный консенсус**. Если статья А цитирует статью Б, это объективное свидетельство связи смыслов, которое может быть не выражено похожими словами в абстракте.

## 2. Суть и применимость Microsoft GraphRAG
Подход Microsoft GraphRAG идет дальше структурных связей. Он преобразует неструктурированный текст в граф знаний (Knowledge Graph):
1.  **Извлечение сущностей:** LLM находит объекты (концепции, методы, авторы) и отношения (например, «метод Х решает проблему Y»).
2.  **Community Detection:** Алгоритмы кластеризации (например, Leiden) разбивают граф на «сообщества» (темы).
3.  **Саммари сообществ:** Для каждого кластера LLM генерирует текстовое резюме.

Когда это оправдано? Это необходимо, когда нужно ответить на вопросы глобального характера («Какие основные проблемы стоят перед областью X?»). Это позволяет модели «видеть» всю картину, а не только релевантные куски текста.
Для личного корпуса до 1000–5000 статей это, скорее, **overkill**. Вычислительные затраты на обработку графа и стоимость API LLM не перевешивают профит от простого полнотекстового поиска с «графовым обогащением» (ранжированием по PageRank).

## 3. Практические компромиссы: с чего начать
Начинать следует с **детерминированного графа цитирований**.
*   **Почему:** Это бесплатно, работает мгновенно через OpenAlex, не требует затрат на токены и не создает галлюцинаций. Структура цитирований уже «вычищена» научным сообществом.
*   **Стратегия:** Используйте OpenAlex для построения графа, а затем применяйте простые графовые алгоритмы (степень центральности, PageRank) для переранжирования результатов вашего текстового поиска.
*   **LLM-граф:** Внедряйте его только тогда, когда почувствуете, что не можете извлечь специфические отношения из текста (например, «какие именно параметры модели Y сравнивались с моделью X»). Это сложная инженерная задача с высоким уровнем шума.

## 4. Рекомендованные источники

1.  **OpenAlex Documentation (API Reference):** Лучший ресурс для понимания того, как вытягивать связи цитирований программно. https://docs.openalex.org/
2.  **Microsoft GraphRAG (GitHub):** Официальный репозиторий с реализацией концепции. Позволяет оценить сложность пайплайна (индексация, кластеризация). https://github.com/microsoft/graphrag
3.  **"Knowledge Graphs for Retrieval-Augmented Generation" (Blog):** Обзорный пост от LlamaIndex, хорошо объясняющий гибридный подход: когда достаточно векторного поиска, а когда нужен граф. https://www.llamaindex.ai/blog/knowledge-graphs-for-rag
4.  **"Citation-based retrieval in science" (Paper):** Исследования по тематике *Citation-based IR* подтверждают, что использование графов цитирований значимо повышает точность поиска по сравнению с обычным BM25/векторным поиском. DOI: 10.1002/asi.24230 (например, работы E. Garfield по тематике Cocitation).
