Этот отчёт сфокусирован на практическом применении графовых структур для построения инструментов автоматизации обзоров литературы (Literature Review).

## 1. Retrieval через граф цитирований: практика и преимущества

Поиск по графу цитирований (Citation Retrieval) обычно реализуется через два метода: расширение (snowballing) и анализ со-цитирования (co-citation).

На практике это работает так: вы выбираете 5–10 «сид-статей» (seed papers), затем скрипт через API (например, OpenAlex) собирает их библиографию (backward references) и список работ, которые цитируют эти статьи (forward citations). 

Преимущества перед текстовым поиском (BM25/Embedding):
- Преодоление терминологического барьера: авторы могут называть одно и то же явление разными словами (например, «Self-Attention» vs «Intra-Attention»), но они почти наверняка будут цитировать одни и те же фундаментальные работы.
- Оценка авторитетности: граф позволяет ранжировать выдачу не по сходству слов, а по топологическим метрикам (PageRank или HITS), выделяя «хабы» (обзоры) и «авторитеты» (ключевые исследования).
- Выявление сообществ: через со-цитирование можно найти альтернативные школы мысли, которые не пересекаются лексически, но изучают одну проблему.

## 2. Суть и применимость Microsoft GraphRAG

Подход Microsoft GraphRAG смещает фокус с метаданных (кто кого цитировал) на содержание текстов. Процесс включает:
1. Извлечение сущностей и связей (Triples: Subject-Predicate-Object) с помощью LLM.
2. Построение графа знаний (Knowledge Graph).
3. Community Detection: алгоритмическое (например, метод Лейдена) разбиение графа на кластеры.
4. Саммаризация сообществ: LLM пишет отчет по каждому кластеру.

Для личного корпуса (100–500 статей) GraphRAG часто является overkill. Основная проблема — стоимость и шум. Извлечение сущностей из сотен PDF-файлов требует тысяч запросов к LLM, а итоговый граф часто замусорен нерелевантными связями. GraphRAG оправдан, когда нужно отвечать на «глобальные» вопросы по всей коллекции («Какие противоречия существуют в методах оценки галлюцинаций?»), а не просто находить куски текста.

## 3. Практические компромиссы: с чего начинать

Для локального research-инструмента оптимальна следующая стратегия:

Этап 1: Детерминированный граф (Metadata-first).
Это «бесплатно» и надежно. Используйте OpenAlex для построения карты цитирований. Это дает скелет исследования. Вы сразу видите структуру области, не тратя токены на чтение каждой статьи. На этом этапе стоит внедрить «Citation Chaining» — автоматический поиск работ, которые связывают две важные для вас статьи.

Этап 2: Текстовый RAG (Local context).
Когда статьи отобраны, используйте классический векторный поиск для навигации по их содержимому. Этого достаточно в 80% случаев для написания обзора.

Этап 3: Легкий GraphRAG (Hybrid).
Вместо полного цикла Microsoft GraphRAG, попробуйте извлекать сущности только из абстрактов или выводов. Это на порядок дешевле, но позволяет строить семантическую карту понятий. 

Вердикт: Начинайте с графа цитирований (OpenAlex) как фильтра, а LLM используйте для синтеза уже отобранного материала. Строить полный граф сущностей по всему корпусу стоит только при наличии неограниченного бюджета и специфической задачи на глобальный синтез знаний.

## Источники

1. Edge, D., et al. (2024). **From Local to Global: A GraphRAG Approach to Query-Focused Summarization**. arXiv:2404.16130. (Основополагающая статья от Microsoft Research про извлечение сущностей и саммаризацию сообществ).
2. **OpenAlex API Documentation** (docs.openalex.org). Разделы по `referenced_works` и поиску через `cites:`. Идеальная база для детерминированного графа.
3. **Connected Papers** (blog.connectedpapers.com). Описание логики построения графов сходства на основе Co-citation и Bibliographic Coupling.
4. **LlamaIndex Property Graph Index**. Документация и туториалы по упрощенной реализации графовых индексов, которые объединяют векторный поиск и графовые связи.
